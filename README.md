# ThreadsFrame

把 Threads 貼文排版成可下載的分享圖，一個可以加到主畫面的 PWA。

## 自動帶入

貼上貼文連結就會自動帶入作者、話題、頭像、內文、時間、四項統計與圖片 —— 你只要挑樣式、存圖。

這需要一支中繼服務（`worker/` 目錄，Cloudflare Worker，免費方案就夠）。
部署方式見 [worker/README.md](worker/README.md)，介面規格見 [worker/API.md](worker/API.md)，部署後把網址填進 app 的「自動帶入」設定即可。

沒有部署也能用，只是要自己複製貼文文字貼上來。

### 有些貼文自動帶入拿不到

中繼服務是以**未登入**的身分去讀 Threads，看到的就是未登入訪客看到的內容。
被 Threads 判定為敏感或成人內容的貼文會被擋在登入牆外 —— 你自己登入的手機上
看得好好的，這裡卻整則讀不到，連內文與統計都拿不到，不是服務壞了。

碰到時 app 會直接說明是這個情形，請改用複製貼文文字貼上，圖片從相簿選。
私人帳號、已刪除的貼文與打錯的連結是同樣的結果，Threads 不區分是哪一種。

## 為什麼需要中繼服務

擴充功能是 content script，跑在 threads.com 頁面裡，直接讀你正在看的那則貼文的 DOM，所以能自動同步作者、話題、頭像、內文、留言。**網頁做不到這件事** —— 它不能讀別的網站的 DOM，只能發 HTTP 請求，而 Threads 沒有任何對瀏覽器開放跨網域的入口：

| 入口 | 結果 |
| --- | --- |
| `graph.facebook.com/…/oembed_threads` | 400，需要 app token 與權限審核 |
| `www.threads.com/oembed` | 302，沒有公開 JSON |
| `/@user/post/CODE/embed` | 200 有內容，但回應沒有 `Access-Control-Allow-Origin` |
| 貼文頁 HTML | 內容需登入態；profile 頁是 JS 算繪，初始 HTML 沒有貼文資料 |

但 Threads **會對爬蟲 UA 提供伺服器算繪版本**（連結預覽就是靠這個）。`worker/` 那支服務
就是在伺服器端用爬蟲 UA 取得該版本並解析，再帶著 CORS 標頭回傳。

代價要說清楚：**啟用自動帶入之後，就不再是「資料完全不離開裝置」**。連結會送到你自己部署的
那支服務去取內容。若不想要，不設定它即可，app 會退回全手動模式，排版與匯出仍然只在本機進行。

## 用法

1. 在 Threads 上點貼文右上角 `⋯` → **複製連結**
2. 貼進 App 的貼上區，按「帶入卡片」—— 作者、話題、頭像、內文、時間、四項統計、圖片與底下的留言會自動帶入
3. 在「樣式」挑一組預設，需要的話再進「畫布與排版」微調
4. 按「存成圖片」

每個欄位帶入後都還能手動改。沒有部署中繼服務時，改成直接複製貼文文字貼上，
名稱、帳號、時間、統計數字一樣會盡量自動拆解，頭像與圖片則從相簿選，留言則手動輸入。

### 想分享某一則留言

Threads 的留言有自己的連結，但**留言頁上沒有原貼文**，所以貼留言連結只會得到
「以那則留言為主體」的卡片。要做成「原貼文＋這則留言」，分兩步：

1. 上面的貼上區貼**原貼文**的連結
2. 展開「留言」，把**留言**的連結貼進某一則的貼上框，按「帶入」

第二步會自動填好那則留言的名稱、帳號、內文、時間、四項統計、頭像與附圖。
自動帶入只收讚數前幾名的留言，這條路則不受排名限制 —— 想放第 20 名那則也行。

留言帶入的是頁面上排在該則貼文後面的回覆，**依讚數由高到低**挑選，最多 4 則。
Threads 的內嵌資料沒有指回父貼文的欄位，只能靠順序判斷，所以偶爾會帶到不相干的
留言 —— 每一則都可以直接改寫或刪除。

**留言預設不畫在卡片上**（會把卡片拉得很長，多數時候要分享的是貼文本身），
原始網址也一樣。留言仍然會自動填進欄位，把「展示留言數目」調上去就立刻出現，
不必重新帶入。

裝到主畫面後也能從 Threads 的分享選單直接分享過來（Web Share Target，Android 支援；iOS 目前不支援分享目標，用複製貼上）。

## 功能

- 8 種樣式預設（純淨白／夜間／雜誌感／便條紙／大字報／柔霧／夕燒玻璃／極光玻璃），一鍵換掉整組排版
- 毛玻璃底板：背景穿透底板時會被模糊，加上細亮邊與投影
- 14 款內建背景 ＋ 26 張紙庫桌布 ＋ 上載自訂底圖，並可存最多 8 張本機背景
- 四種字體：黑體／襯線／圓體／等寬
- 留白、文字尺寸、圓角、底板透明度、底板色、文字色（色票與 hex 皆可輸入）
- 比例：直式 4:5 / 直式 9:16 / 方形 / 自動高度。這是**最小高度**，內容更長時卡片會自己往下長，不會裁掉
- 時間格式可切換：絕對（2026-08-07 07:40）或相對（6 小時）
- 四項互動統計：讚、留言、轉發、分享
- 作者列標帳號而非顯示名稱（與 Threads 一致），話題接在後面：`帳號 › 話題`
- 顯示切換：頭像、互動統計、時間、貼文圖片（可指定 1–4 張）、原始網址
- 留言最多 4 則，可自動帶入、貼連結帶入或手動輸入，可指定展示數目，
  各自設定名稱、帳號、內文、時間、讚數、頭像與附圖
- 版面照 Threads 的串文排法：頭像自己佔左邊一欄，內文、圖片、統計與留言縮排
  對齊帳號，貼文頭像有一條細線連到留言頭像
- 貼文圖片一行兩張，依方向自動配置：橫圖與方圖用正方格，直圖用 2:3 卡位，
  一直一橫同行時等高但各自分配寬度；張數為奇數時最後一張獨佔整排。
  格與格之間留一道細縫
- 遮蔽作者身分（名稱、帳號、頭像一起蓋掉，留言者同步匿名化）
- 單張貼文圖片維持原比例完整顯示，不裁切；多張時各自填滿格子（邊緣會裁掉），
  同一行才對得齊
- 輸出固定 1080px 寬，與裝置螢幕無關
- 重設只還原排版，不動已經輸入的貼文內容

### 關於背景素材

紙庫裡的每一張都是程式畫出來的（`src/backgrounds.ts` 的 paint 函式），
沒有打包任何系統桌布或第三方素材 —— 那些有版權，也會讓 repo 肥上數十 MB。
縮圖與輸出共用同一個 paint 函式，所以選單看到的就是實際會輸出的樣子。

## 開發

```sh
npm install
npm run dev      # 開發伺服器
npm run build    # 型別檢查 + 打包到 dist/
npm run preview  # 預覽打包結果
npm run icons    # 重新產生 public/icons/*.png

npm run test:worker  # 取文代理的解析與錯誤分流
npm run test:render  # 卡片排版（需先 build，會開一顆 Chromium）
```

`test:render` 用純色測試圖檢查多圖排版的規則本身 —— 同排等高、右緣對齊、
落單獨佔整排 —— 而不是比對截圖。截圖會因為機器字體不同而假性失敗，
規則檢查不會。它也不連 Threads：樣本貼文會被刪除或被擋在登入牆外，
靠網路的測試遲早會因為與程式無關的原因而壞掉。

算繪走 Canvas 2D（`src/render.ts`），不是 DOM 截圖 —— 輸出尺寸才能固定，也避開 `html2canvas` 那類方案在 iOS Safari 上的光柵化失敗。

## 隱私

沒有後端。貼文內容、圖片、自訂底圖都只在瀏覽器記憶體裡，重新整理就消失；只有排版偏好會寫進 `localStorage`。
